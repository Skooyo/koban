Koban receipt reading: plan

Part A fixes item and price pairing on the phone. Part B adds Claude as a fallback. Part C sets up AWS for 20 to 50 friends. Status: plan only, no code changed. Updated 2026-11-12: invite codes, 10 receipts a day, Gemini removed.

Summary
  1. The phone keeps ML Kit and the receipt rules. Most receipts never leave the phone.
  2. When the items do not add up to the total, you can tap "Read with Claude". The phone sends the photo to your server.
  3. Friends join with an invite code from you. Each code works on 2 phones, and you can cancel it.
  4. One small Linux server on AWS is enough for 50 people. It holds the Claude key and the limits.
  5. Gemini goes out of the app completely.

Part A. Fix item and price pairing on the phone

You used the document scanner and some names did not pair with their prices. The scanner flattens the page, but a long receipt still curls a little. The rules pair a name and a price only when their vertical centers are within half a line height (ReceiptRules.rows()). On a wide receipt, a small slope moves the price more than that.

B2. A friend joins with an invite code

An invite code replaces the "5 new devices per IP" limit. That IP limit was a problem: 10 friends on the same Wi-Fi share one IP, so the 6th friend would be blocked. With invite codes, only people you choose can make a token.

sequenceDiagram
  participant You as You (admin)
  participant Srv as Your server
  participant F as Friend's phone
  You->>Srv: koban-admin new-code "Aisyah"
  Srv-->>You: Code K7QX-M2PA (2 devices)
  You->>F: Send the code on WhatsApp
  F->>Srv: POST /v1/devices { invite: K7QX-M2PA }
  Srv->>Srv: Code exists, not cancelled, fewer than 2 devices?
  Srv-->>F: { token }
  F->>F: Save token in DataStore
  Note over You,Srv: To stop a person: koban-admin cancel "Aisyah". All their tokens stop.

Part C. AWS setup for 20 to 50 friends

Recommendation: one small Linux server. 50 people at 10 receipts a day is at most 150 calls a day, about one call every 10 minutes. Most of the time is waiting for Claude, not CPU. A server with 0.5 to 1 GB of memory is enough. If your current Claude server is a Linux VPS, put the new service on it and pay nothing extra.

C5. Option not chosen: serverless

API Gateway + Lambda + DynamoDB also works and needs no OS updates. It has 3 services to set up instead of 1 server, and the invite and limit logic moves into DynamoDB. Choose it only if you want no server to look after. For 50 friends, the single server is less work.

Part D. Update check in the app

Yes, this works without the Play Store. The same server tells the app which version is the newest.

sequenceDiagram
  participant App as Koban app
  participant Srv as Your server
  App->>Srv: GET /v1/app/latest (at app start, at most once a day)
  Srv-->>App: { versionCode: 5, versionName: "1.4", url, sha256, notes }
  alt server versionCode > installed versionCode
    App-->>App: Show "Update to 1.4" dialog with the notes
    App->>Srv: Download the APK
    App->>App: Check sha256, then open the Android installer
  end
ItemDetail
Signing keyRequired first. Android installs an update only when it has the same signature. Today's APK uses the debug key from this PC. Make one release keystore, keep 2 backups, and sign every APK with it. If you lose it, every friend must uninstall and install again.
App changesPermission REQUEST_INSTALL_PACKAGES, a FileProvider for the downloaded file, one dialog. Android asks each friend once to allow installs from Koban.
Server changesA latest.json file and the APK, served by Caddy. To publish: increase versionCode, build, copy 2 files.
TimeKeystore 20 min, app 1.5 h, server 15 min
